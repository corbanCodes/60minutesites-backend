Onboard a paying client (the Todd flow)

  1. Customers → Add — name, email, cell. Copy the generated password; text it to them.
  2. Their site repo: if it doesn't exist yet, create github.com/new → e.g. corbanCodes/clientname, push their index.html (or download from Sites → HTML and upload it there).
  3. Netlify: Add new site → Import from GitHub → pick that repo → attach their custom domain (Domain settings → Add domain → follow the DNS records it shows you).
  4. Sites → + New site — business name, Owner = the client, paste the repo (corbanCodes/clientname) in "Import from GitHub" → Create. The site now lives here AND is linked to the repo.
  5. Test the loop: open the editor, change one word, Save. Within a minute the commit appears in GitHub and Netlify redeploys their domain. If Save says "github: failed", the token is missing that repo — edit the token's repo list at github.com/settings/personal-access-tokens.
  6. Forms → Create — name it after them, Owner = the client. In the editor, "+ Form" and pick their form. Their leads now flow to their account (you still see everything as admin) and email them via Resend.
  7. Log in as them once (their email + password) to see exactly what they see: Dashboard, their site, their leads, their forms — nothing of yours.

If something breaks

  • Client wrecked their page: Sites → Undo save restores the previous version (and re-pushes to GitHub). Every save keeps the last 20 versions.
  • Form redirect typo / wrong URL: forms can't be edited yet — delete and recreate (the embed code changes; re-paste it).
  • Railway deploy loses data: it shouldn't (Postgres) — if it ever does, check the app service still has DATABASE_URL = ${{'{{'}}Postgres.DATABASE_URL{{'}}'}}.
  • Live funnel (/start on the marketing site): still Formspree on purpose during the ad test — don't switch it until the day-7 read is done.
